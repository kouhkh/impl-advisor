# 代码库与运行顾问：概要设计

> 状态：模块边界修订版，2026-10-12  
> 首个试点：Planora「技术规格书语气改写」  
> 详细模块与部署见 [`CODING_AGENT_ADVISOR_SERVICE_ARCHITECTURE.md`](./CODING_AGENT_ADVISOR_SERVICE_ARCHITECTURE.md)。

## 1. 设计判断

1. 项目方只提供代码和运行材料的只读访问，不向目标代码库添加提示词、导航、索引或技能。
2. 系统由一个薄 Runner 编排 PinAsk、代码/运行读取、DSH 和外部会话记录。
3. DSH、证据检查和回答组织是 Runner 内的组件，不是互相独立的产品层。
4. 顾问在目标代码库之外生成少量查询笔记；首问没有笔记时仍能使用通用搜索。
5. Planora P0 在 Mac 本地运行；项目网络受限时，才把同一个 Runner 放到项目方网络内。

## 2. 要解决的问题

专家对着页面结果问“为什么会这样”。顾问需要同时读取两类材料：

| 问题 | 需要的材料 | 能回答到哪里 |
|---|---|---|
| 实现解释 | 源码、配置、代码版本 | 哪个模块、规则或调用链导致行为 |
| 运行解释 | 运行输入、结果、中间产物、日志、运行版本 | 这一次实际使用了什么材料和流程 |

只有代码材料时，只能解释实现，不能声称还原某一次运行。

## 3. 系统组成

```text
PinAsk 页面
   ↓ 页面事实 + 问题
薄 Runner
   ├─ 代码只读 + 运行材料只读
   ├─ DSH Adapter（Flash 默认）
   ├─ 证据检查与回答组织
   └─ 外部 Advisor Workspace
```

系统模块的职责和边界见架构文档。它们不要求对应多个进程：Planora P0 可以由一个 Mac 本地 Runner 调用现有 DSH 完成。

## 4. 两条接入轴

### 轴 A：页面上下文采集

| 档位 | 项目方页面改造 | 内容 | 阶段 |
|---|---:|---|---|
| 零改造 | 否 | URL、选中 DOM、文本、祖先结构、时间；截图可选 | P0 |
| 复用已有线索 | 否 | 页面已经显示的任务、运行或版本线索 | P0，有则采 |
| 页面适配器 | 仅接入层 | 在长期定位失败时补充 task/run/version 等字段 | 按失败信号 |

`project` 和 `environment` 由顾问配置绑定。PinAsk 不负责把 UI 映射到源码，也不持有 SSH、数据库或模型凭据。

### 轴 B：运行材料访问

| 方式 | 适用情况 | 阶段 |
|---|---|---|
| 固定导出目录 | Planora P0 的本地实验 | P0 |
| 已有只读查询命令 | 项目已有查运行和产物的命令 | P0/P1 |
| SSH 只读搜索 | 测试环境材料只在内网 | P1 |
| Runtime Adapter | 第二个项目重复出现同类接入 | 后续 |

轴 B 不是页面接入的第四档。没有 `run_id` 时必须搜索或浏览材料；有多个候选时要列出并追问，不能拼接不同运行。

## 5. 外部 Advisor Workspace

顾问资料不写入目标代码库：

```text
<advisor-data>/<project>/<environment>/
  project.json
  notes/                 # 少量顾问查询笔记
  sessions/<session-id>/
  confirmed-facts.jsonl
```

笔记用于减少重复搜索，不是项目正式文档，也不替代业务质量标准。内容分为：

| 状态 | 含义 |
|---|---|
| `observed` | 从代码、页面或运行材料直接读取 |
| `derived` | Agent 根据证据推导的待核对内容 |
| `confirmed` | 专家或研发确认过 |
| `stale` | 来源版本或环境发生变化 |

## 6. 项目方最低接入

项目方需要提供：

1. 项目和环境名称；
2. 代码只读入口；
3. 运行材料只读入口：导出目录、只读命令、SSH 或已有 API 至少一种；
4. 必要的网络、账号或 SSH 权限；
5. 能判断回答是否有用的人。

项目方不需要：

- 添加 `docs/advisor/`、`AGENTS.md`、skill 或索引；
- 维护顾问提示词和查询脚本；
- 改业务代码或开放写权限；
- 运行独立 Runner（Planora P0 由我们在 Mac 启动）。

## 8. Planora P0 验收

1. 在 PinAsk 中点选页面元素并提问；
2. Runner 读取 Planora 代码和实际运行材料；
3. DSH 返回分层回答：代码事实、运行事实、推导和缺失材料；
4. 专家可以在同一页面继续追问；
5. 会话、证据和查询笔记写入目标代码库之外；
6. 代码、运行材料和业务服务没有被修改。
